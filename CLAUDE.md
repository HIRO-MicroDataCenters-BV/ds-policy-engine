# CLAUDE.md — ds-policy-engine Development Guide

## Project Overview
FastAPI-based policy-as-code microservice. SQLAlchemy 2.0 async + Alembic + SQLite (Postgres-ready). OPA runs as a sidecar in Kubernetes (toggleable) and as a compose service locally. Template: [ds-catalog](https://github.com/HIRO-MicroDataCenters-BV/ds-catalog).

## Layout (matches ds-catalog template)
```
server/                                FastAPI app (Poetry, Python 3.12)
  app/
    main.py                            FastAPI bootstrap, lifespan, routers
    settings.py                        pydantic-settings (env prefix DS__)
    database.py                        async engine, init_db, close_db, get_session_factory
    migrate_db.py                      seed-from-JSON bootstrap
    conftest.py                        root pytest fixtures
    core/                              domain layer
      usecases.py                      I*Usecase ABCs + concrete impls
      validators.py                    validate_role / validate_permissions
      entities.py                      domain Pydantic types
      context.py                       per-call Context dataclass
      exceptions.py                    PolicyEngineError + subclasses
      constants.py                     default Role / Permission enums
      rego_generator.py                Rego compilation strategy
      policy_engine.py                 PolicyEngine Protocol
      opa_adapter.py                   OPA HTTP impl
      repository/                      persistence layer
        repositories.py                RuleRepository Protocol
        sqlite_rule_repository.py
        db_models.py                   SQLAlchemy ORM
        tests/                         repository unit tests
      tests/                           core unit tests (usecases, rego, etc.)
    rest_api/                          HTTP layer
      depends.py                       DI wiring (get_*_usecase)
      response.py                      ApiResponse envelope helpers
      serializers.py                   request/response Pydantic schemas
      routes/                          one file per concern
        tests/                         route integration tests (TestClient)
  alembic/                             migrations
  charts/ds-policy-engine/             Helm chart (published to gh-pages)
  policies/                            Rego seed (seed_rules.json)
api/                                   openapi.yaml (regenerated by pre-commit + CI)
client/                                auto-generated Python SDK (do not edit)
tools/                                 version.sh, extract_openapi.py, client_generator/
.github/workflows/                     server.yaml (test/build/publish), client.yaml (PyPI)
docs/index.html                        Swagger UI landing (gh-pages root)
docker-compose.yml                     local dev: OPA + backend
```

Routes depend on the `I*Usecase` interfaces (in `core/usecases.py`); the
DI wiring in `rest_api/depends.py` picks the implementation. Routes do
not orchestrate repositories or adapters directly — that's the use-case
layer's job. To swap OPA for another engine, change one line in
`depends.py`; routes don't move.

## Code Quality — run locally before committing
All four are enforced via `.pre-commit-config.yaml` and `server.yaml` CI.

```bash
cd server
poetry run mypy app                            # config: mypy.ini
poetry run isort app --check --diff
poetry run flake8 app --config .flake8         # line length 88
poetry run black app --check --diff
poetry run pytest
```

Install the hooks once:
```bash
pip install pre-commit && pre-commit install
```

Two additional pre-commit hooks always run and regenerate files:
- `openapi` — runs `tools/extract_openapi.py` → writes `api/openapi.yaml`.
- `generate_client` — runs `tools/client_generator/generate.py` → regenerates `client/` (requires Docker).

CI fails if `git diff` shows drift in either.

## Workflow: Commits
- Lint changed files only:
  ```bash
  git diff --name-only develop | grep '\.py$' | xargs poetry --project server run black --check
  git diff --name-only develop | grep '\.py$' | xargs poetry --project server run flake8
  ```
- Commits must be authored solely by the committer — no co-author trailers.

## Workflow: Pull Requests
- Branch from `develop`. `main` is release-only.
- PR target is `develop`: `gh pr create --base develop`
- Copilot auto-reviews. After pushing:
  ```bash
  gh api repos/HIRO-MicroDataCenters-BV/ds-policy-engine/pulls/<PR>/comments
  ```

### Resolving Copilot/review comments
1. Reply:
   ```bash
   gh api repos/HIRO-MicroDataCenters-BV/ds-policy-engine/pulls/<PR>/comments/<CID>/replies \
     -X POST -f body="Fixed."
   ```
2. **Resolve** the thread (not just minimize):
   ```bash
   # get thread IDs
   gh api graphql -f query='query { repository(owner:"HIRO-MicroDataCenters-BV", name:"ds-policy-engine") { pullRequest(number:<PR>) { reviewThreads(first:20) { nodes { id isResolved } } } } }'
   # resolve each
   gh api graphql -f query='mutation { resolveReviewThread(input:{threadId:"<THREAD_ID>"}) { thread { isResolved } } }'
   ```
   `minimizeComment` hides but does NOT resolve. Always use `resolveReviewThread`.

## Configuration
All runtime config via env vars prefixed `DS__` (see `server/.env.template`). Key vars:

| Var | Purpose |
|-----|---------|
| `DS__DATABASE_URL` | SQLAlchemy URL; SQLite by default, Postgres works |
| `DS__OPA_BASE_URL` | OPA endpoint; `127.0.0.1:8181` in-pod (sidecar) |
| `DS__CORS_ALLOWED_ORIGINS` | Comma-separated origins; empty disables middleware |
| `DS__DOCS_ENABLED` | `false` disables `/docs`, `/redoc`, `/openapi.json` |
| `DS__POLICIES_DIR` | Seed rules dir (image default `/code/policies`) |
| `DS__NODE_NAME` | Site tag (ki/hus/uva/local); used for default institute |

## Database & Migrations
- SQLAlchemy 2.0 async, Alembic in `server/alembic/`.
- New migration:
  ```bash
  cd server
  poetry run alembic revision --autogenerate -m "describe change"
  poetry run alembic upgrade head
  ```
- `alembic/env.py` reads `DS__DATABASE_URL` (falls back to `DATABASE_URL`).

### CheckConstraint migration safety
Never assume a constraint name — production may hold auto-generated names. Drop pattern (Postgres):
```python
from alembic import op
from sqlalchemy import text

def _drop_check_constraint_on_column(table_name, column_name):
    if op.get_bind().dialect.name != "postgresql":
        return  # SQLite has no pg_constraint
    conn = op.get_bind()
    result = conn.execute(text(
        "SELECT conname FROM pg_constraint c "
        "JOIN pg_attribute a ON a.attnum = ANY(c.conkey) "
        "  AND a.attrelid = c.conrelid "
        "WHERE c.conrelid = CAST(:table_name AS regclass) "
        "AND c.contype = 'c' "
        "AND a.attname = :column_name "
        "AND array_length(c.conkey, 1) = 1"
    ), {"table_name": table_name, "column_name": column_name})
    for row in result:
        op.drop_constraint(row[0], table_name, type_="check")
```
Use `CAST(:param AS regclass)` — the `::regclass` syntax collides with SQLAlchemy's `:param` binds. Always guard PG-only paths behind a SQLite dialect check because tests run on SQLite.

## Versioning & Release
`VERSION` is the base. `tools/version.sh` (in CI) derives per-build app/chart/docker versions.

- Branch/PR push → non-PEP440 dev version (`0.1.0+dev3-mybranch-411fa4aa`).
- Tag `N.N.N` → clean semver (Docker + Helm chart + PyPI client).

Pushing a tag `0.1.1` ships Docker + Helm + PyPI + GitHub Release.
